# Carbon Ledger

An interactive reference for country-level CO<sub>2</sub> emissions and each country's
share of observed warming, built from the Global Carbon Project via
[Our World in Data](https://github.com/owid/co2-data).

Plain static site — no build step, no bundler. D3 is the only runtime dependency
and is loaded from a CDN.

## Running it

The datasets are fetched at startup, so the folder has to be served over HTTP;
opening `index.html` directly from disk hits the browser's `file://` fetch
restriction and the page shows a red load-error banner.

```bash
npm start                  # http://localhost:5173
```

Or without npm:

```bash
python -m http.server 5173 # http://localhost:5173
```

## Refreshing the data

The JSON under `/data` is a snapshot, but not a hand-made one — it is
regenerated by a pipeline, and every year label in the UI ("Latest year",
card titles, the scenario baseline, download filenames) derives from the data
at runtime, so a refreshed snapshot relabels the whole page by itself.

```bash
python3 scripts/refresh_data.py            # fetch, validate, rewrite /data
python3 scripts/refresh_data.py --dry-run  # report what would change
```

The script is standard-library Python: it pulls
[owid/co2-data](https://github.com/owid/co2-data) and the Climate Watch
sector dataset, rebuilds `countries/world/history/income/sectors/meta.json`,
and refuses to write anything that fails validation (country counts, world
totals, a latest year that would move backwards), so a bad upstream day can't
clobber a good snapshot. `geo.json` (static boundaries) and `netzero.json`
(hand-curated from the ECIU tracker) are left alone — review net-zero targets
by hand when refreshing.

`.github/workflows/refresh-data.yml` runs the same script monthly (the Global
Carbon Project releases annually, usually November) and commits only when the
data actually changed, so a static host deploying from this repo stays current
with no manual rebuild. It can also be triggered from the Actions tab.

## Layout

```
.
├── index.html          # document shell + page markup
├── src/
│   ├── css/styles.css  # all styles, light/dark via CSS custom properties
│   └── js/app.js       # data loading + all rendering (D3)
├── data/               # six JSON datasets, fetched at startup
│   ├── geo.json        # country boundaries (GeoJSON FeatureCollection)
│   ├── countries.json  # latest per-country metrics, keyed by ISO-3
│   ├── world.json      # world totals by year, 1900-present
│   ├── history.json    # per-country annual series, keyed by ISO-3
│   ├── income.json     # World Bank income-group aggregates
│   ├── netzero.json    # net-zero target year + status, major emitters
│   ├── sectors.json    # GHG emissions by sector (CO₂e), Climate Watch
│   └── meta.json       # refresh date + latest data years (footer credit)
├── scripts/
│   └── refresh_data.py # regenerates /data from upstream, with validation
└── design/             # design canvas working files (.dc.html artboards)
```

The page is one 12-column bento grid: the metric picker sits above it and drives
the map, the ranking and the table alike. Grid cells are named `.cell-map`,
`.cell-rail`, `.cell-compare`, `.cell-resp`, `.cell-trend`, `.cell-sectors`,
`.cell-area`, `.cell-targets`, `.cell-scenario` and `.cell-table` in
`src/css/styles.css`.

"Saved views" stars the current combination — metric, pinned country set,
selection, scenario settings, explicit theme — under a name in `localStorage`,
restorable in one click. Each saved view (and the "Share & reuse" link) uses a
compact code, e.g. `?v=w.CHN-USA..p50-2040` (metric+theme · pins · selected ·
scenario), parsed alongside the legacy long-form params, so shared links stay
short. The scenario controls are part of the URL state either way.

"Share & reuse" can also export the current view as a citation-ready PNG
share card (deck 16:9 or social 1200×630). Cards are drawn directly on a
canvas — no capture library — adapt to the view (global map, single country,
or the pinned comparison), follow the active theme, and carry the source
line, refresh date, and a link that reproduces the exact view.

The sector card splits each country's emissions into energy, industrial
processes, agriculture, waste, and land use & forestry — all gases as CO₂e
(Climate Watch sub-sectors grouped in `renderSectors`), since agriculture is
mostly methane and N₂O. Land use can be a net sink and is drawn left of the
zero axis at reduced opacity. Its rows follow the pinned/selected countries.

Up to four countries can be pinned for side-by-side comparison — from the
compare tray under the metric picker, the detail panel, the star on ranking and
table rows, or by shift-clicking the map. Pins keep a stable color each
(`--cat-1..4`) and thread through every view: map outlines, the top-15 ranking,
a dedicated side-by-side card, the trend chart and its table, the targets
table, a "Pinned countries" scenario group, and the share URL (`?pin=CHN,USA`).

`src/js/app.js` fetches all six files in parallel and then calls `boot(DATA)`,
which holds the rendering logic. To add a dataset, add an entry to the
`DATASETS` map at the top of the file — it is picked up automatically and
arrives on the `DATA` object under the same key.

## Deploying

Any static host works. Upload the repository root as-is — GitHub Pages,
Netlify, Cloudflare Pages, S3. There is nothing to compile.

## Data sources

- [Global Carbon Project / Our World in Data](https://github.com/owid/co2-data)
- [Net Zero Tracker](https://eciu.net/netzerotracker) — target years and status
- [Climate Watch via Our World in Data](https://ourworldindata.org/grapher/ghg-emissions-by-sector) —
  greenhouse gas emissions by sector (`data/sectors.json`)
